## 1. 背景与目标

### 1.1 背景

需要批量产出中文 AI 科普类视频，形态参照参考样本：单期 8–10 分钟，第一人称叙事口播，画面为"固定舞台布景 + 角色立绘 + 信息卡片 + 逐句字幕条 + 章节进度条"的合成图层。一期视频约含 200 个画面节拍、160 句口播字幕。

人工完成一期需 2–4 人日（脚本、分镜、素材、配音、剪辑）。本项目目标是将其压缩为"输入一个选题，输出一条可发布的成片"，人工只参与选题确认与最终审片。

### 1.2 系统目标

| 编号 | 目标 | 可量化指标 |
|---|---|---|
| G1 | 全自动产出成片 | 从确认选题到输出成片，全程无需人工编辑视频 |
| G2 | 保证成片可用率 | 首次输出即可发布（无需返工）的比例 ≥ 80% |
| G3 | 控制单期耗时 | 单期端到端耗时 ≤ 60 分钟（含 AI 调用与渲染） |
| G4 | 风格一致性 | 同系列所有成片的视觉元素、音色、节奏参数完全一致 |
| G5 | 可回溯可续跑 | 任一期视频在任一阶段失败均可从失败点续跑，不重复已完成的工作 |

### 1.3 非目标（本期不做）

- 不做真人出镜、实拍素材、绿幕合成
- 不做多语言配音（仅中文简体）
- 不做视频发布到平台的自动上传（仅产出本地文件 + 元数据）
- 不做弹幕/评论互动分析
- 不做移动端 App

## 2. 术语与角色定义

| 术语 | 定义 |
|---|---|
| 系列（Series） | 一组风格、音色、角色、章节结构一致的视频，如本系统的"AI 科普"系列 |
| 一期（Episode） | 一条最终输出的视频及其全部中间产物 |
| 镜头（Shot） | 画面发生一次变化的单元，对应一句（或半个短语的）口播。样本中平均时长 3 秒，中位数 2.5 秒 |
| 字幕条（Subtitle Bar） | 画面底部居中、深灰底白字的字幕元素，每 6–8 字逐段出现 |
| 章节进度条（Section Bar） | 画面最底部、横向排列的章节标签，当前章节高亮 |
| 信息卡片（Card） | 画面中部承载内容的容器，分对话气泡、终端窗口、浏览器页面、图标、纯文字五类 |
| 角色资产包（Character Pack） | 一个角色的全部固定素材：立绘、表情、动作、配色、声音、说话风格 |
| 画面节拍 | 两次视觉变化之间的间隔 |

### 2.1 角色设定

本系列固定使用角色 **洛琪希·米格路迪亚（Roxy Migurdia）**，来自《无职转生》。造型基准见 `assets/roxy_reference.webp`（本地参考图，不随公开仓库分发）：浅蓝紫色长发、右侧单股麻花辫、黑色宽檐尖顶魔女帽、象牙白立领衬衫与深色领结、卡其色长风衣、深棕皮质腰挂、白色短裤、黑色过膝袜与象牙白过膝长靴。角色资产以非商业同人创作为前提使用，相关约束见第 11 章。

角色在系统中的定位是 **"吐槽型搭档 + 视觉锚点"**，承担三类职责：

1. 出现在约 60% 的镜头中，提供画面的固定识别符号
2. 以台词形式对旁白的论述做吐槽或补充（占比约 20% 的句子）
3. 用表情和动作传递情绪节奏（疑惑、得意、无奈、震惊）

### 2.2 角色语气规范

| 场景 | 语气要求 | 反例（不可出现） |
|---|---|---|
| 吐槽旁白 | 简短、犀利、口语化，单句 ≤ 15 字 | 长篇说教、书面语 |
| 表达困惑 | 真诚提问，带轻微自我怀疑 | 阴阳怪气、讽刺 |
| 讲解原理 | 认真、有条理，可以稍慢 | 卖萌、敷衍 |
| 被夸或被认可 | 害羞、别扭、转而嘴硬 | 过度得意、失态 |

性格基调为"认真但有点天然呆、嘴硬心软、对不专业的事会直接吐槽"。禁止出现与角色年龄设定不符的内容，禁止恋爱向描写。

## 3. 用户与使用场景

### 3.1 用户角色

| 角色 | 职责 | 使用频率 |
|---|---|---|
| 运营（选题人） | 提供选题候选，确认选题 | 每周 1 次 |
| 审片人 | 查看成片，决定通过/重做/局部修改 | 每期 1 次 |
| 开发/运维 | 维护流水线、查看失败日志、补充素材 | 按需 |

### 3.2 主要用例

**UC-01 生成一期视频（主流程）**

1. 运营输入选题候选（支持手动输入或从信息源抓取），或直接跳过、指定一个选题
2. 系统生成脚本，输出到待确认状态
3. 运营/审片人在 Web 界面查看脚本全文，可编辑、可重新生成单段
4. 确认后，系统自动完成分镜、配音、渲染，产出成片
5. 审片人查看成片与质检报告，选择"通过"或"重做"

**UC-02 局部修改**

审片人发现第 42 句台词表述不好、或第 12 分钟某个画面字幕溢出。系统支持：修改这一句 → 只重新生成该句的配音、对应镜头与前后 2 个镜头的转场 → 局部重渲染并拼接，**不重跑全片**。局部重渲染耗时 ≤ 5 分钟。

**UC-03 从失败点续跑**

任一阶段失败（如 TTS 接口超时、渲染进程崩溃），系统记录失败节点，修复后从该节点续跑，已完成节点直接命中缓存。

**UC-04 查看质检报告**

审片人查看质检结果，包含：脚本字数与节奏、配音时长异常项、抽帧画面截图、字幕与口播对齐检查，标注为 `通过 / 自动修复 / 人工介入` 三档。

**UC-05 角色资产更新**

开发者替换或新增角色立绘，系统自动校验尺寸、透明通道、命名规范，不合规直接拒绝入库。

## 4. 功能需求

优先级定义：**P0** = 首版必须；**P1** = 首版之后尽快；**P2** = 可延后。

### 4.1 选题模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-01 | 支持手动录入选题（标题 + 一句话说明 + 目标时长） | P0 |
| F-02 | 支持从多个信息源（RSS、GitHub Trending、指定关键词）抓取候选选题，每日生成候选清单 | P1 |
| F-03 | 对每个候选选题给出结构化的"适配性评估"：是否适合本视觉模板、建议章节数、预估时长 | P1 |
| F-04 | 选题确认必须由人工操作，系统不得自动推进到脚本阶段 | P0 |

### 4.2 脚本模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-05 | 采用"大纲 → 分段 → 逐句"三级生成，每级可单独重新生成 | P0 |
| F-06 | 每句台词标注说话人（旁白 / 洛琪希）、所属章节、字数 | P0 |
| F-07 | 每句字数 ≤ 25 字；超过则自动拆分或标记违规，阻断进入下一阶段 | P0 |
| F-08 | 全文总字数与目标时长匹配：目标字数 = 时长(分钟) × 327，误差 ≤ ±10% | P0 |
| F-09 | 脚本需覆盖预定义的章节结构（默认 8 段：问题 / 概念 / 原理 / 踩坑 / 解决 / 推广 / 预告等，可配置） | P0 |
| F-10 | 洛琪希的台词需符合 2.2 语气规范，生成结果由规则检查 + 模型自检双重把关 | P0 |
| F-11 | 支持在 Web 界面编辑任意句子，编辑后自动重算 F-07 / F-08 校验 | P0 |
| F-12 | 禁止词表可配置，命中即阻断 | P1 |

### 4.3 分镜模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-13 | 每句台词对应一个镜头，输出为结构化数据（见 6.2 shot 表结构） | P0 |
| F-14 | 分镜只能在系统预定义的视觉语法内选择（卡片类型、角色姿势、位置、背景），越界即判定失败并重试 | P0 |
| F-15 | 节奏规则硬性约束：① 连续 3 个镜头不得使用同一卡片类型；② 角色连续出现不得超过 4 个镜头；③ 每小节的最后一个镜头须为全场图标/纯文字镜头；④ 单镜头时长 1.5–6 秒 | P0 |
| F-16 | 镜头时长由对应句子的配音时长驱动，不写死 | P0 |
| F-17 | 视觉模型评审分镜表，对"连续镜头单调""信息与画面不匹配"等问题打回重排 | P1 |
| F-18 | 输出前生成全片节奏曲线（镜头数 / 章节 / 卡片类型分布），供人工快速判断 | P1 |

### 4.4 配音与对齐模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-19 | 按句独立合成音频；任一句失败可单独重试 | P0 |
| F-20 | 同一系列使用固定 `voice_profile`（音色 ID、语速倍率、情绪），不得在期与期之间漂移 | P0 |
| F-21 | 支持至少两种音色（旁白 / 洛琪希），并在脚本阶段完成分配 | P0 |
| F-22 | 获取字级时间戳，用于字幕条逐段出现；若 TTS 不提供，则用强制对齐工具补齐 | P0 |
| F-23 | 生成整片音轨时支持音色切换与句间停顿控制（默认 120–250ms，按标点调整） | P0 |
| F-24 | 音量统一标准化到 -14 LUFS | P1 |

### 4.5 画面渲染模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-25 | 信息卡片必须用 HTML 模板渲染后截图生成，不得使用图像生成模型生成含文字的卡片 | P0 |
| F-26 | 卡片模板库至少包含：对话气泡（旁白/AI 两种样式）、终端窗口、浏览器页面、图标、纯文字 | P0 |
| F-27 | 角色立绘、背景、章节进度条作为固定图层，全片复用 | P0 |
| F-28 | 字幕条按字级时间戳逐段显隐，单屏不超过 20 字 | P0 |
| F-29 | 支持基础动效：淡入淡出、轻微平移、角色待机呼吸、卡片弹入 | P0 |
| F-30 | 输出规格：1920×1080、25fps、H.264、AAC 48kHz | P0 |
| F-31 | 渲染支持并行，且按镜头粒度缓存；局部修改时只重渲染受影响镜头 | P0 |
| F-32 | 输出封面图（从指定镜头抽取或模板生成）与视频元数据（标题、简介、章节时间点） | P0 |
| F-43 | 支持用图像生成模型生成原创角色/背景/装饰素材候选，人工筛选后入库；记录 prompt、模型、seed、参考图 | P0 |
| F-44 | 角色/背景素材生成后固定资产化，不得每期重新生成；含文字的信息卡片仍按 F-25 用 HTML 渲染 | P0 |
| F-45 | 图像生成 provider 可配置；未配置时使用占位素材，不影响渲染链路 | P1 |

### 4.6 质检模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-33 | 文案检查：字数区间、单句长度、字数总量、章节覆盖、禁止词 | P0 |
| F-34 | 配音检查：合成成功率、单句时长异常检测（如 < 0.5s 或 > 1.5 倍预期） | P0 |
| F-35 | 画面检查：关键抽帧（每镜头首帧）用视觉模型或 DOM/几何规则检查角色裁切、文字溢出、空白镜头；文字溢出优先用 DOM 规则 | P0 |
| F-36 | 对齐检查：字幕播出时间与音频实际发声音节的时间偏差 ≤ 150ms | P1 |
| F-37 | 质检结果分三档，并给出可执行的修复建议；自动修复项需说明修复方式 | P0 |

### 4.7 任务与运维模块

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-38 | 一期视频的全流程以状态机管理，状态见 6.3 | P0 |
| F-39 | 任一阶段失败可重入，已完成节点命中缓存 | P0 |
| F-40 | 所有 AI 调用与渲染步骤记录耗时、模型版本、token 成本 | P0 |
| F-41 | 提供 Web 界面：选题列表、脚本编辑、分镜预览、成片播放、质检报告 | P0 |
| F-42 | 提供任务队列监控与告警（失败率、耗时超阈值） | P1 |

## 5. 角色资产包需求

洛琪希资产包是系列视觉识别的核心，单独定义。

### 5.1 立绘规格

| 项目 | 要求 |
|---|---|
| 格式 | PNG，RGBA 透明背景 |
| 画布尺寸 | 1080 × 1920 px（竖版全身） |
| 构图 | 角色脚底对齐画布底边；最高点（含魔女帽尖）距画布顶边 ≤ 60px，适配"站立于木纹台面"的构图 |
| 发型 | 浅蓝紫色长发，右侧单股麻花辫垂至腰下，发尾以深色缎带束起；刘海遮眉，两侧鬓发垂肩 |
| 头饰 | 主造型为黑色宽檐尖顶魔女帽，帽带为白色上下边 + 橄榄金纹样；备用草帽造型（深色帽带）用于轻松段落与片尾 |
| 服装 | 象牙白立领衬衫（胸前黑色细带与圆形黑扣装饰）+ 深色领结；卡其色长风衣（黑色翻边袖口、金色扣饰、长后摆）；深棕皮质腰封与侧挂包；白色荷叶边短裤；黑色过膝袜（袜口白色菱形格纹）；象牙白过膝长靴（棕色鞋底、黑色鞋跟） |
| 描边 | 统一外描边（建议 4–6px 深色描边），风格与信息卡片的手绘描边一致 |
| 位置锚点 | 提供 `anchor_x`（画面水平位置，默认左 28%）与 `anchor_y`（脚底距画面底部距离，默认 210px）两个参数 |
| 命名 | `roxy_{expression}_{pose}_{variant}.png`，如 `roxy_puzzled_standing_01.png` |
| 数量 | 首版 ≥ 18 张 |
| 生成方式 | 外包/自绘，或用图像生成模型产出候选；AI 生成需固定 prompt、参考图和 seed，人工筛选后入库，入库后作为固定资产，不得每期重生成 |
| 参考图 | `assets/roxy_reference.webp`（角色造型参考图，来源：萌娘百科；仅作内部造型基准，不进入成片画面；本地保留，不随公开仓库分发） |

> 角色造型参考图仅本地保留，不随公开仓库分发；公开仓库只包含文字规格与占位素材。
>
> AI 图像生成仅适用于原创角色/背景/装饰。Seedream 实测会对洛琪希名称、参考图或高度相似特征返回 `PolicyViolation`；洛琪希 pack 需自绘/外包，不能依赖 AI 复刻。

### 5.2 必备表情与姿势清单

| 编号 | 表情 | 姿势 | 叙事场景 |
|---|---|---|---|
| R-01 | 平静 | 站立 | 默认、旁白讲述时的背景 |
| R-02 | 疑惑 | 单手托腮、歪头 | 提问、"为什么" |
| R-03 | 惊讶 | 双手抬起 | 翻车、意外结果 |
| R-04 | 无奈 | 摊手 | 吐槽、"你看看" |
| R-05 | 得意 | 叉腰 | 讲对原理、"我说对了吧" |
| R-06 | 思考 | 抱臂低头 | 推导、权衡 |
| R-07 | 专注 | 拿平板/笔记本 | 看代码、看截图 |
| R-08 | 害羞 | 低头、手扶头 | 被夸奖 |
| R-09 | 认真 | 站立前倾 | 强调关键结论、章节收尾 |
| R-10 | 放松 | 坐姿、喝茶 | 片尾、轻松段落 |
| R-11 | 指向 | 单手推出 | 引导看卡片内容 |
| R-12 | 震惊 | 后仰 | 重大数据、反转 |
| R-13 | 微笑 | 站立微笑 | 开头、结尾 |
| R-14 | 沉思 | 手抵下巴、目视远处 | 章节过渡 |
| R-15 | 气鼓鼓 | 抱臂扭头 | 被吐槽后 |
| R-16 | 开口说话 | 站立、口部张开 | 讲解原理、对话进行中 |

> 说明：编号 R-01 至 R-16 为表情/姿势组合的主清单。每个组合可提供 1–3 个变体，实际入库数量以 5.1 的 ≥18 张为准。参考图左侧三张头像（平静、开口说话、困扰）为首版表情的绘制基准；其中 R-01 / R-02 / R-16 建议各提供"闭口 / 开口"两个变体，用于口播过程中的表情切换。后续可按数据补充（某个组合使用频次高但表情不够贴切时优先补）。

### 5.4 音色要求

洛琪希的音色需满足：年轻女声、音调略偏高、语速中等偏快、情绪表达自然（吐槽时不夸张），可用 TTS 音色克隆或高质量预设音色。参考 CV 为小原好美（日配）：音色清亮、冷静中带一点无奈与天然感，中文 TTS 选型以此气质为目标。**旁白与洛琪希必须为两个明显可区分的音色。**

### 5.5 章节进度条

8 个章节标签全片固定，当前项黑色高亮 + 小花图标。标签名称在系列创建时一次性确定，不允许每期不同。

## 6. 数据需求

### 6.1 核心实体

```
series       id, name, voice_profile, section_labels[8], character_pack_id, watermark, template_version
episode      id, series_id, title, topic, target_duration_s, status, output_path, created_at
script_line  id, episode_id, seq, speaker, section, text, char_count
shot         id, episode_id, script_line_id, seq, duration_ms, card_type, card_payload,
             character_image, character_position, bg, transition, cache_key
asset        id, type(character|card_shot|audio|background), path, tags, checksum
render_job   id, episode_id, node, status, attempt, error, started_at, finished_at
review       id, episode_id, check_item, level(通过|自动修复|人工介入), detail, evidence_path
```

### 6.2 关键约束

- `shot.cache_key` = hash(script_line.text + card_type + card_payload + character_image + template_version)，用于渲染缓存
- 同一 `episode` 下 `shot.seq` 唯一且连续
- `script_line.char_count` 由系统计算，不接受前端传入
- `review` 中任一 `人工介入` 项未处理时，`episode.status` 不得进入"待发布"

### 6.3 状态机

```
DRAFT(选题中) → TOPIC_CONFIRMED(选题待确认) → SCRIPTING(写脚本)
→ SCRIPT_REVIEW(脚本待确认) → STORYBOARDING(分镜) → VOICING(配音)
→ ALIGNING(对齐) → RENDERING(渲染) → QC(质检)
→ READY(待发布) → PUBLISHED(已发布)
```

- `QC` 不通过时，根据 `review` 结果回退到具体阶段（脚本问题回 `SCRIPT_REVIEW`，配音问题回 `VOICING`，画面问题回 `RENDERING`）
- 所有状态转换记录操作人（人 / 系统）与时间戳
- `TOPIC_CONFIRMED` 与 `SCRIPT_REVIEW` 为人工闸口，系统不得自动跳过

## 9. 验收标准

以下每条均为可测试项，验收时逐条核对。

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A-01 | 端到端生成 | 输入一个选题，无人工编辑成片，成功输出 8–10 分钟视频 |
| A-02 | 时长控制 | 输出视频时长与目标时长偏差 ≤ 10% |
| A-03 | 速度控制 | 全片语速在 300–350 字/分钟区间 |
| A-04 | 镜头密度 | 全片镜头数 ≥ 150，平均单镜头时长 2–4 秒 |
| A-05 | 节奏规则 | 抽样 50 个镜头，F-15 四条规则无违反 |
| A-06 | 字幕正确性 | 随机抽 20 句，字幕文字与脚本完全一致，无错字、无溢出卡片 |
| A-07 | 字幕对齐 | 随机抽 20 句，字幕出现时间与音频发音偏差 ≤ 150ms |
| A-08 | 卡片文字 | 抽检全部信息卡片，文字内容与脚本意图一致，无乱码、无错字（P0 卡点） |
| A-09 | 角色一致性 | 全片角色为同一形象，无形象漂移；裁切问题率 ≤ 2% |
| A-10 | 音色一致性 | 同系列两期视频的音色主观听感一致；旁白与洛琪希音色可区分 |
| A-11 | 合格率 | 连续生成 5 期，首次输出即可发布的比例 ≥ 80%（即 ≤ 1 期需重做） |
| A-12 | 局部修改 | 修改任意一句，≤ 5 分钟内输出新成片，且未修改部分逐帧不变 |
| A-13 | 断点续跑 | 人为中断渲染，重启后从断点继续，已完成镜头不重复渲染 |
| A-14 | 质检可用性 | 故意注入 3 类缺陷（超长句、TTS 失败、文字溢出），质检报告全部检出 |
| A-15 | 成本可见 | 单期报告准确列出 token 用量、TTS 调用次数与费用估算 |
| A-18 | AI 素材入库 | 用图像生成模型产出 ≥3 个原创角色/背景候选，记录 prompt/model/seed，人工筛选后入库并在成片中复用；含文字卡片仍为 HTML |

### 11.2 技术风险

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-01 | TTS 的"AI 感"明显 | 观感差于真人样本，是最大的质量短板 | 选高质量音色；脚本中刻意加入口语停顿与语气词 |
| R-02 | 渲染耗时长 | 单期超时 | 镜头级缓存、并行渲染、优先 720P 试渲染 |
| R-03 | 角色立绘不足 | 大量镜头被迫复用同一姿势，画面单调 | 首版 ≥ 18 张；建立"高频场景补图"机制 |
| R-04 | 脚本质量不稳定 | 成片内容空洞 | 三级生成 + 人工确认闸口；用已发布的好成片做 few-shot |
| R-05 | 卡片文字溢出 | 直接触发 A-08 失败 | 模板层面做字数上限与自动缩放，渲染后自动截断检测 |
| R-06 | 视觉评审误判 | 无效重排，浪费成本 | 评审结论只做"打回建议"，不直接阻断；设置重排上限 2 次 |
